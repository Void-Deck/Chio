# Chio 0.2.0 release record

Chio 0.2.0 packages terminal maps, explicit map services, unified styles and
instrumentation on SwiftTUI merged revision
`7e62e95c913508f4fef42db36fde6fd60acb541c`. This source release is in preparation;
final Chio qualification and publication remain pending. It remains experimental
personal software, built with Codex assistance and human curation, under the MIT license. We cannot
vouch for production stability; APIs and behavior may change.

Once published, the [GitHub release](https://github.com/echoz/Chio/releases/tag/v0.2.0)
will identify the immutable Chio release commit and final installation snippet.
This record describes the approved scope, historical baseline and pending final
checks. The earlier
[0.1.0 record](0.1.0.md) remains specific to that release.

## Component coverage

The release retains the controls, search, forms, feedback, Markdown, links and
example compositions from 0.1.0. These are the principal additions:

| Area | Included in 0.2.0 | Boundary |
| --- | --- | --- |
| Geographic maps | World/street geometry, pan/zoom, selection, annotations, route overlays, adjustable detail and outline presentation | Native Canvas renders bounded Mercator geometry; polar and dense-data limits remain |
| Online tiles | Explicit OpenFreeMap discovery and bounded tile loading, cancellation and replacement | Applications opt in; no implicit online or bundled-source fallback |
| Storage | Persistent raw-tile cache and programmatic read-only tile packs | Applications supply pack bytes; no provider archive downloader, PMTiles or MBTiles reader |
| Place lookup | Forward Photon search and a separate reverse lookup capability/client | Applications select endpoints, invocation and result handling |
| Routing | Two-point OSRM adapter, checked route geometry/metadata and contrasting route overlays | No routing engine, turn instructions, automatic rerouting or default live endpoint |
| Styling | Immutable `ChioStyle` and inherited `.style(...)`, with default/light/btop/opencode presets and Chio list-row padding | Applications retain layout, breakpoints and data; native `List` rows require authored padding |
| Instrumentation | Measurement gauges, segmented readouts, target dials, native labelled-content styling and time-aware history | Applications supply values, samples, timing and thresholds |
| Native integration | Merged SwiftTUI #57 revision, retaining 0.18.0 disclosure, Spacer and measured-row corrections and adding row-geometry focus recovery, eager-table placement and outline focus corrections | Final merged-pin qualification pending; intermittent tab timing and native measurement diagnostics remain documented |

The [showcase](https://echoz.github.io/Chio/) separates reusable views, native
styles and example applications. Its recordings use local fixtures; they do not
demonstrate live provider availability. [Usage](../Usage.md) and
[examples](../Examples.md) describe the public APIs and launch commands.

## Installation

Requires Swift 6.4+, macOS 15+ or ordinary Linux with the Swift/Foundation runtime.
Chio exports one library product. Applications also depend on SwiftTUI for native
views and the runtime.

Copy the **exact Chio release revision** from the GitHub release notes. Direct
SwiftTUI requirements must match
`7e62e95c913508f4fef42db36fde6fd60acb541c` (merged SwiftTUI #57, after 0.18.0).
SwiftTUI 0.18.0 does not contain that correction. Update both manifest
requirements and resolve `Package.resolved` together. Chio's other direct
dependency revisions are unchanged by the release preparation.

Version-based Chio requirements such as `from: "0.2.0"` or `exact: "0.2.0"`
cannot consume the current revision-pinned dependency graph. The release tag
names a reproducible source checkpoint; it does not change that SwiftPM constraint.
No prebuilt binaries or fully static Linux executables are included.

## Migration from 0.1.0

- Replace `ChioTheme` with `ChioStyle`, `.chioTheme(...)` with `.style(...)`, and
  `\.chioTheme` with `\.chioStyle`. These aliases are removed by explicit choice;
  this is a breaking API migration. Historical style, spacing and treatment
  function-reference overloads are removed too. Use their current signatures or
  explicit closures around labelled calls with defaults.
- `DurationText` retains its default plain-text formatting, rounding and original
  initializer references. Segmented presentation is opt-in. Timing remains
  application-owned, as it was in 0.1.0.
- Review `.btop` presentation: the inherited style now installs border headings.
  OpenCode adds one cell above and below Chio searchable rows. Customize
  `spacing.listRowVerticalInset` to choose 0...32 cells per side; zero stays compact.
  Native `List` rows can apply the value through ordinary `.padding(.vertical, ...)`.
- Tests must distinguish checked membership from native focus. SwiftTUI 0.18.0
  uses `▌` for checked list membership and `>` for the active unchecked row.
  Inspect public focus regions for focus instead of treating membership paint
  as a cursor. Keep selection and activation assertions independently.
- Recheck terminal capabilities when upgrading. A generic `xterm-256color`
  value alone no longer implies OSC 8 links or synchronized output. For a known
  true-color terminal over SSH, forward or explicitly provide `COLORTERM=truecolor`.
- Map services are explicit effects beside `MapView`. Adding the map view does
  not authorize network requests, choose an endpoint or create a disk cache.

## Release verification

`7d44bd6bd85290f2c6e3526cf19e6647d551797c`. Its tree matches the independently
reviewed PR #17 candidate. The user then added list-row spacing and the breaking

The historical spacing candidate fails two dynamic mixed-height focus checks on

focus to the preceding row. The unchanged spacing, retained list and appearance
checks pass in both configurations against an isolated candidate for
[SwiftTUI #57](https://github.com/SwiftTUI/swift-tui/pull/57). #57 merged on

## Remaining boundaries

Provider downloads for offline packs remain paused. Resumable downloads, archive
formats and automatic pack/network fallback require separate decisions. Online
geometry covers a supported OpenMapTiles subset; buffered tile overlap, polygon
cut edges, terminal-cell color collisions and dense-area rejection remain possible.

Forward/reverse Photon integration has bounded live-provider evidence. Routing
has deterministic and real loopback adapter coverage; no public routing endpoint
was exercised in the recorded checks. Neither establishes service uptime or
universal geographic quality. Live navigation and Pitwall integration are separate.

Fully static Linux linking remains blocked by upstream portability gaps. The
[dependency record](../Decisions/Dependencies.md#static-linux-blocker) and
[native integration record](../Decisions/NativeIntegration.md) retain the specific
limits. Downstream application adoption requires each application's own checks;
publishing this release does not complete that rollout.
