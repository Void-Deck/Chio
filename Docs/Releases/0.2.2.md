## Changes from 0.2.1

- Keep the active palette command visible in short terminals.
- Recover previously visible focused controls after viewport or content geometry
  changes, while preserving intentional scrolling.
- Correct retained focus reads and stacked observation callbacks. Form validation
  and diff navigation retain their public interaction checks.
- Adopt native navigation that skips disabled checklist rows. Disabled choices
  remain visible and untoggleable, including when already checked.
- Keep checklist search editable when no enabled result can receive focus.
- Adopt native two-axis Home/End behavior in the viewport example.
- Preserve inherited Darwin output policy and bound saturated-socket writes.
- Serve pending startup input after required initial presentation and focus settle.
- Avoid the Apple SwiftBuild private-focus metadata link failure without changing
  public list behavior or native focus ownership.
- Include the naming-review workflow and release compiler-context support in
  EngineeringRules 0.1.10. Retain the single documented scratch-state exception.

Public Chio API names, `ChioStyle` values and style configuration remain unchanged
from 0.2.1. There is no new renderer, focus owner or local SwiftTUI patch.
The [0.2.0 record](0.2.0.md) preserves the earlier feature scope and migration
from 0.1.0; 0.2.1 added source-root guides and development checks.

## Installation and migration

Requires Swift 6.4+, macOS 15+ or ordinary Linux with the Swift/Foundation runtime.
Install Chio revision `4ded80f870fb2c92c92d7d402fd71d42213ecee8`.
Direct SwiftTUI requirements must match
`3999a9a57dde52fb00aa98952460b0819a0641bf`.
Update both manifest requirements and resolve `Package.resolved` together.
Other direct dependency revisions remain unchanged.

Version requirements such as `from: "0.2.2"` or `exact: "0.2.2"` cannot consume
this revision-pinned dependency graph. The release tag identifies a reproducible
source checkpoint. Consumers install that checkpoint by its immutable commit.

Applications should verify disabled-row navigation, empty or disabled-only search
results, short palettes, dynamic scroll layouts and their own terminal lifecycle.
Checked membership and keyboard focus are distinct. Update expectations that
previously focused disabled rows or treated Home/End as vertical-only navigation.
Use release for normal verification; add debug runs for named debug-only contracts.

## Limits and consumer rollout

Native collection-realization diagnostics and the documented
[integration boundaries](../Decisions/NativeIntegration.md#remaining-boundaries)
remain. SwiftTUI #62 is included. The private focus-type workaround remains
part of this release, with its specific compatibility limit documented above.
Release verification does not establish a debug-only startup correction.
No prebuilt binaries or fully static Linux executables are included. Static-musl
distribution, live provider availability and universal SSH behavior are unverified.

Marquee, Blackbox and Pitwall are the confirmed application consumers in the local
inventory. Adoption requests reached all three owners and their tasks have started.
Final adoption remains in progress. Each owning task must verify its exact release
adoption and preserve its platform, diagnostic, terminal-lifecycle and publication contracts. Publishing
Chio or sending an adoption request does not establish downstream adoption.
